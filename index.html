流程详细说明
🧠
AI-1 查询重写器
新增
  • 接收用户自然语言提问，AI-2 永远不知晓真实名称
  • 查询 entity_mapping 表，匹配别名/缩写，统一替换为脱敏标识（如 项目-ase237）
  • 时间语义解析：上个月 / 上季度 → 标准日期区间
  • 术语归一：平台 / 信道 / 渠道 → 统一为标准业务术语
  • 实体未命中时提示用户澄清，不透传原词
🗂
entity_mapping 映射表
新增
  • 核心维护资产，新增游戏/项目时必须同步录入别名
  • 字段：alias（别名列表）/ standard_name（脱敏标识）/ type（game/company/dept）/ sensitive_level（I/II/III）
  • 支持多别名：跃动小子 / 跃动 / 跃动游戏 → 同一脱敏标识
  • 未录入的实体 → AI-1 识别失败 → 提示用户，不进入 AI-2
🗄
数据表分级标准
数仓维护
级别策略典型场景
🔴 I 类禁止传输手机号/身份证/支付原文
🟡 II 类脱敏后可传订单明细/结算数据/项目主数据
🟢 III 类可直接传出维度配置/汇率/渠道类型
🪞
孪生视图机制
数仓配置
  • 每张 II 类表对应一个已脱敏的孪生视图
  • AI 发起查询时，API 自动将 SQL 中的原始表名替换为孪生视图
  • AI-2 执行的始终是孪生视图，无法访问原始数据
  • II 类表未配置孪生视图 → 检测一直接打回
  • III 类表无需配置孪生视图，直接查询
🔍
结果二次扫描
  • 对 AI-2 返回的数据文件进行全量扫描
  • 检测项：手机号（11位数字）、身份证号（18位含字母）、公司主体（entity_mapping 中标注的敏感实体）
  • 发现任一敏感数据 → 立即打回，阻止交付
  • 全部通过后才允许结果交付给用户
🔓
反脱敏（可选）
  • 分析结果默认以脱敏标识呈现（项目-ase237）
  • 如需还原真实名称，通过独立解密平台操作
  • 该功能按需开放，需额外申请权限，有独立审计日志
  • 解密平台与 AI 分析链路物理隔离
